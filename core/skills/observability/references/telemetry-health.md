# Telemetry health verification

Use one bounded, non-sensitive marker generated by a representative test operation. Record its
timestamp, service or resource identity, expected signals, and cleanup or retention behavior.

## Evidence ladder

1. **Bootstrap:** the intended SDK or provider initializes before relevant libraries and reports no
   initialization conflict. This proves configuration only.
2. **Emission:** an in-process or local diagnostic exporter observes the expected signal with the
   correct name, unit, resource, and redacted attributes.
3. **Propagation:** downstream work carries the expected parent context across every real boundary.
4. **Receiver:** the collector or agent accepts the marker on the intended endpoint and pipeline.
5. **Processing:** filters, transforms, sampling, batching, and redaction retain the intended signal
   and remove forbidden data.
6. **Export:** exporter self-telemetry shows success without unexplained refusal, drop, retry
   exhaustion, queue saturation, or stale timestamps.
7. **Backend:** an independent query retrieves the marker with the expected resource identity and
   signal relationships.
8. **Use:** the derived query, SLI input, alert test, or diagnostic view changes as specified.

A higher step does not erase a contradiction at a lower step. When access stops at one layer, report
the last verified step and the next discriminating observation.

## Safety checks

- Generate no production customer payload solely for a telemetry test.
- Search the marker across all enabled exporters to detect duplication or misrouting.
- Test a forbidden sensitive field and verify absence at the export boundary without placing a real
  secret or personal value in the test.
- Test a bounded high-cardinality attempt and verify rejection, normalization, or relocation.
- Exercise an async or queue boundary and verify one trace tree rather than disconnected roots.
- Exercise a rare error under the configured sampling policy and state any remaining blind spot.
- Validate rollback by disabling or reverting the instrumentation without breaking the application.
